> এটি [ইংরেজি মূল লেখার](../../../../docs/guide/11-javascript.md) অনুবাদ। পার্থক্য থাকলে ইংরেজি সংস্করণটিই সঠিক। অনুবাদটি AI-এর সাহায্যে করা এবং লেখক যাচাই করেছেন।

# ১১. JavaScript-এ কম্পাইল

`runescript build` একটি প্রোগ্রামকে এমন একটি JavaScript মডিউলে কম্পাইল করে, যা
ব্রাউজারে বা Node.js-এ চলে। প্রোগ্রামটি RuneScript-এর নিয়মগুলো বজায় রাখে: টাইপ
চেকার যা প্রত্যাখ্যান করে তা এখনো প্রত্যাখ্যাত, আর ইন্টারপ্রেটারে যা রানটাইম এরর
হতো, JavaScript-এও তা একই রানটাইম এরর, একই কোড, বার্তা ও সোর্স-অবস্থানসহ।

```sh
runescript build examples/fizzbuzz.rsc            # writes examples/fizzbuzz.js
runescript build -o web/app.js examples/hello.rsc # choose the output file
node examples/fizzbuzz.js                         # runs it; main's result is the exit code
```

`--target js` হলো ডিফল্ট, এবং আপাতত একমাত্র টার্গেট। কয়েকটি ফাইলের একটি প্রোগ্রাম
(দেখুন [প্যাকেজ ও ফাইল](12-packages-and-files.md)) একটি মডিউলে পরিণত হয়, আর
রানটাইম এরর জানায় কোন ফাইলে সেটি ঘটেছে।

## ওয়েব পেজে মডিউলটি ব্যবহার

আউটপুট হলো নির্ভরতাহীন, স্বয়ংসম্পূর্ণ একটি ES2022 মডিউল। এটি এক্সপোর্ট করে `run`,
যা `main` কল করে তার এক্সিট কোড ফেরত দেয়, এবং `RuneScriptError`, প্রোগ্রাম কোনো
রানটাইম এরর দিয়ে থেমে গেলে `run` যেটি throw করে।

```html
<pre id="out"></pre>
<script type="module">
  import { run, RuneScriptError } from "./fizzbuzz.js";
  const out = document.getElementById("out");
  try {
    run({ trace: (line) => { out.textContent += line + "\n"; } });
  } catch (e) {
    if (!(e instanceof RuneScriptError)) throw e;
    out.textContent += e.message; // e.g. "fizzbuzz.rsc:6:15: error ASX-RUN-002: …"
  }
</script>
```

`options.trace` `trace` আউটপুটের প্রতিটি লাইন পায়। এটি না দিলে লাইনগুলো যায়
`console.log`-এ। একটি `RuneScriptError`-এর আরও আছে `code`, `file`, `line`, `col`
ও `detail` (অবস্থান বাদ দিয়ে বার্তাটি)।

## অনুবাদের পরেও কঠোর টাইপিং কীভাবে টিকে থাকে

JavaScript-এ সংখ্যার টাইপ একটিই এবং কোনো স্ট্যাটিক টাইপ নেই, তাই RuneScript কোড
তৈরির আগে যা যা পারে সব যাচাই করে, আর বাকিটা পাহারা দেয় তৈরি হওয়া কোড নিজে:

| RuneScript-এর নিয়ম | সাধারণ JavaScript | তৈরি হওয়া কোড |
|---|---|---|
| প্রতিটি মানের টাইপ তার ঘোষিত টাইপ | ভেরিয়েবলে যা খুশি থাকতে পারে | কম্পাইলের সময় যাচাই হয়, তারপর কোনো কোড লেখার আগে টাইপসহ IR-এ আবার যাচাই হয়। কখনো যাচাইহীন রূপান্তর তৈরি হয় না। |
| `int` ও `uint` 32-বিট; ওভারফ্লো হলে `ASX-RUN-002` | `2147483647 + 1` হলো `2147483648` | পূর্ণসংখ্যার প্রতিটি `+ - * / %` একটি সীমা-যাচাইয়ের মধ্য দিয়ে যায়, যা প্রোগ্রাম থামিয়ে দেয় |
| `/` দশমিক অংশ ছেঁটে ফেলে | `7 / 2` হলো `3.5` | ছেঁটে ফেলা ভাগ |
| শূন্য দিয়ে ভাগ হলে `ASX-RUN-003` | `Infinity` বা `NaN` | পূর্ণসংখ্যা ও ফ্লোট দুটির জন্যই যাচাই হয় |
| `float32` 32 বিটে রাউন্ড হয় | একটিই 64-বিট সংখ্যার টাইপ | `float32`-এর ফল `Math.fround`-এর মধ্য দিয়ে যায়, এবং float32-এর সবচেয়ে ছোট অঙ্কে দেখানো হয়; `float` ও `float64` হলো JavaScript সংখ্যা (IEEE, `NaN` ও `Infinity`-সহ, AS3-এর মতো) |
| `(int) "12x"` একটি `TypeError` throw করে | `parseInt("12x")` হলো `12` | ইন্টারপ্রেটারের মতোই পার্স করার নিয়ম |
| রানটাইম এরর ধরা যায় এমন এরর-মান | এক্সেপশন যেকোনো মান হতে পারে | এরর হলো RuneScript-এর এরর অবজেক্ট; catch ক্লজ তাদের টাইপ যাচাই করে; কল-গভীরতার এরর প্রতিটি catch ক্লজ পেরিয়ে যায় |
| কল সর্বোচ্চ ১০,০০০ স্তর গভীর হতে পারে (`ASX-RUN-001`) | হোস্টের উপর নির্ভরশীল স্ট্যাক | গোনা হয়। হোস্টের স্ট্যাক আগে ফুরিয়ে গেলে, সেটিও `ASX-RUN-001` |
| `std:string`-এর অবস্থান হলো UTF-8 বাইট অফসেট | স্ট্রিং UTF-16 | অফসেট রূপান্তর করা হয়, তাই সব টার্গেটে `string.index("5€x", "x")` হলো `4` |
| `std:string`-এর বড়-ছোট হাতের অক্ষর ও হোয়াইটস্পেস Go মেনে চলে | `"ß".toUpperCase()` হলো `"SS"` | Go-র `unicode` প্যাকেজ থেকে তৈরি টেবিল, তাই ফল হুবহু এক |

যেমন, একই প্রোগ্রাম দুটি টার্গেটেই একই জায়গায় থামে:

```actionscript
package demo;

public int main() {
    int big = 2147483647;
    trace(big * big); // runtime error: ASX-RUN-002
    return 0;
}
```

বার্তাটি হলো `integer overflow: 2147483647 * 2147483647 =
4611686014132420609 does not fit in 'int'`, যা হুবহু হিসাব করা, যদিও একটি
JavaScript সংখ্যা ওই গুণফল ধরে রাখতে পারে না।

টেস্ট-সংগ্রহ প্রতিটি উদাহরণ ও টেস্ট প্রোগ্রাম ইন্টারপ্রেটার ও Node.js দুটিতেই
চালায়, এবং হুবহু একই আউটপুট, এক্সিট কোড ও এরর দাবি করে। এটি প্রতিটি `std:string`
ফাংশনকে এলোমেলো অ-ASCII লেখার উপর Go-র ফাংশনের সঙ্গে তুলনাও করে।

## JavaScript টার্গেটের সীমাবদ্ধতা

- **স্ট্যাকের গভীরতা।** ব্রাউজার ও Node.js-এ প্রায়ই ১০,০০০ নেস্টেড কলের আগেই
  স্ট্যাক ফুরিয়ে যায়। তখন প্রোগ্রামটি রিকার্শনের কোনো একটি কলের জায়গায়
  `ASX-RUN-001` ("the JavaScript host ran out of stack") দিয়ে থামে। জায়গাটি সবসময়
  সেটি নয়, যেটি ইন্টারপ্রেটার জানাত।
- **খুব লম্বা স্ট্রিং।** JavaScript ইঞ্জিন স্ট্রিংয়ের দৈর্ঘ্যের একটি সীমা রাখে (মোটামুটি
  2<sup>29</sup>–2<sup>30</sup> UTF-16 একক)। `string.repeat` বা `string.replace`-এর
  ভেতরে সেটি ছাড়িয়ে গেলে `ASX-RUN-004` জানানো হয়।
- **এখনো JavaScript-এর সঙ্গে আদান-প্রদান নেই।** প্রোগ্রাম JavaScript ফাংশন বা DOM
  কল করতে পারে না, আর JavaScript কেবল `run` কল করতে পারে। JavaScript-এ কল করার
  পরিকল্পনা আছে `use "js:<module>";` হিসেবে, টাইপসহ ঘোষণা দিয়ে, যাদের মান
  RuneScript-এ ঢোকার সময় যাচাই করা হবে।
